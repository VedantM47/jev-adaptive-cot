<objective>
Establish the retrieval stack foundation that the Phase 4 tracer builds on: (1) a typed, YAML-driven `RetrievalConfig` (NFR-07: all configuration via YAML, no hard-coded paths) nested in `ExperimentConfig`, and (2) the FAISS + sentence-transformers dependency set, installed only after the protocol-mandated package-legitimacy human checkpoint.

Purpose: The research Package Legitimacy Audit flagged `faiss-cpu` and `sentence-transformers` as `[SUS]` (a false-positive signal — latest-release date and a missing download count — but the protocol still requires a blocking human gate before install). `torch` is added as a direct dependency only to pin it to the PyTorch CPU wheel index (keeps Linux CI from pulling multi-GB CUDA wheels); it was not in the audit table, so it is treated as `[ASSUMED]` and goes through the same gate. The config task runs first so it can finish while the human reviews the packages.

Output: `RetrievalConfig` + `retrieval:` YAML block + tests; `pyproject.toml`/`uv.lock` with the locked retrieval stack and a mypy override that keeps `mypy --strict` fast and clean.

Planner decisions (Claude's discretion per 04-CONTEXT.md; all implementation choices are discretionary there):
- Embedding model default `sentence-transformers/all-MiniLM-L6-v2` (research A4). Its input window is 256 word-pieces, so the default chunk window is 120 words with a 20-word overlap (about 17%). That fits the model window with headroom. Research A3 suggested 512–1024-token chunks, but MiniLM would silently truncate chunks that long.
- All retrieval paths/params live in YAML so the ingest CLI (plan 04-05) and future controller read them from config.
</objective>
